# Вайб-кодинг в Termux Assistant AI — план

> Черновик от 2026-10-03. Статус: **не реализовано**, обсуждается архитектура.

## Идея

Дать приложению возможность создавать и развивать **новые Android-проекты с нуля** прямо на телефоне — по аналогии с вайб-кодингом на ПК (Cursor, Claude Code), но в рамках `Termux Assistant AI`.

Ключевое отличие от текущего режима **Dev**: агент сам решает, какие файлы создать/изменить/удалить. Пользователь не выбирает файл из списка — он ставит задачу.

## Что уже есть (переиспользуем)

| Компонент | Статус | Роль |
|---|---|---|
| WebView + JS-мост (TermuxSend/ReadPost/FindAndClick) | OK | Ядро: вставка промпта, чтение ответа |
| `runFullCycle` | OK | Отправка задачи, ожидание, применение |
| `waitForDevReply` | OK | Ожидание стабильного ответа агента |
| `ai-tasker-server` (HTTP IPC, порт 8767) | OK | Принимает команды от приложения |
| `aib-auto` + AiBridgeService | legacy | Не трогаем |
| `ai-dev` (1 файл, жёсткий промпт) | узко | Заменяем |

## Архитектура (три слоя)

### 1. Сервер (`ai-tasker-server`) — новые команды

- `project_list:` — список проектов из `~/vibe/`
- `project_tree:<name>` — структура проекта (пути + размеры, без содержимого)
- `project_read:<name>:<path>` — содержимое файла
- `project_write:<name>:<path>:<b64>` — записать файл (создать/перезаписать)
- `project_delete:<name>:<path>` — удалить файл
- `project_build:<name>` — запустить `build.sh`, вернуть stdout/stderr/rc
- `project_new:<name>:<template>` — создать проект из шаблона
- Перед применением изменений: **бэкап** в `~/vibe/.backups/<name>-<ts>/`

### 2. Формат ответа агента (задаётся жёстким промптом)

Блоки вида (тройные backtick'и в реальном промпте):

    === FILE: src/com/example/app/MainActivity.java ===
    (код)
    === FILE: res/layout/activity_main.xml ===
    (код)
    === DELETE: old.txt ===

Никаких "верни полный файл целиком" — только реально изменённые файлы.

### 3. Логика в `MainActivity` — новый режим "Новый проект"

    vibeSend(task):
      project = currentProject                     // ~/vibe/<name>
      tree    = httpTask("project_tree:" + project)
      prompt  = VIBE_PROMPT.format(tree, task)
      send to DeepSeek -> wait stable reply
      ops     = parseFileBlocks(reply)             // WRITE / DELETE
      показать превью -> пользователь жмёт "Применить"
      for op in ops: httpTask("project_write:...")
      result  = httpTask("project_build:" + project)
      if result.rc != 0:
          sendErrorToChat(result)                  // возврат в чат -> цикл
      else:
          показать "Готово: APK в ..."

## Промпт агента (черновик)

    Ты — автономный программист. Работаешь над Android-проектом на Java.

    СТРУКТУРА ПРОЕКТА (папка ~/vibe/<name>/):
    === PROJECT: <name> ===
    <дерево файлов>

    СБОРКА: bash build.sh (aapt2 + javac + d8 + apksigner, в Termux)

    ЗАДАЧА:
    <текст задачи от пользователя>

    ФОРМАТ ОТВЕТА (строго!):
    - Верни ТОЛЬКО файлы, которые нужно создать или изменить.
    - Каждый файл — блоком:
        === FILE: <путь относительно корня проекта> ===
        (код)
    - Если файл нужно удалить: === DELETE: <путь> ===

    ПРАВИЛА:
    - Не объясняй. Только блоки.
    - Возвращай ПОЛНОЕ содержимое каждого указанного файла (не diff).
    - Пиши компилируемый Java 8 (aapt2/javac/d8 из Termux).
    - R-класс генерируется aapt2 в build/gen — не создавай его вручную.
    - Не создавай .bak, patch.py и прочий мусор в проекте.

## Что происходит при ошибке сборки (цикл)

Приложение ловит `rc != 0` от `project_build`, шлёт в чат:

    Сборка упала.
    Ошибка:
    <javac stderr>

    Исправь. Верни файлы в том же формате.

Агент возвращает только исправленные файлы. Цикл повторяется до успеха или лимита.

**Лимит:** 5-7 итераций или 10 минут — потом стоп и показать пользователю последний вывод.

## Пути

- Проекты вайб-кодинга: `~/vibe/<name>/`
- Бэкапы: `~/vibe/.backups/<name>-<ts>/`
- APK на выходе: `/sdcard/Download/<name>-<HHMMSS>.apk`

## Шаблоны проектов

- **android-java** — build.sh (aapt2+javac+d8+apksigner) + минимальный MainActivity + AndroidManifest + res/
- **java-cli** — build.sh (javac + jar) без Android
- (обсуждается) **web** — простой index.html + assets/

## Этапы работ

| Этап | Содержание | Оценка |
|---|---|---|
| 1. MVP серверной части | команды `project_*` в `ai-tasker-server`, ручная болванка проекта, проверка: показать дерево, прочитать/записать файл, собрать | ~1-2 ч |
| 2. Цикл вайб-кодинга | VIBE_PROMPT + парсер блоков + превью + автоцикл по ошибкам сборки в MainActivity | ~2-3 ч |
| 3. Экран управления | список проектов, создание из шаблонов, удаление, выбор активного | ~1 ч |

Итого: **~5 часов** работы (плюс отладка).

## Отличия от текущего Dev

| Сейчас (Dev) | Вайб-кодинг |
|---|---|
| Пользователь выбирает файл из списка | Агент сам решает, какие файлы создать |
| Возвращается 1 файл | N файлов + удаления |
| Применяется мгновенно | Превью -> применить |
| Нет цикла по ошибкам сборки | Автоцикл "упало -> отправил -> починил" |
| Работает только с `termux-ai-kit` | Работает с любым проектом в `~/vibe/` |
| Промпт "верни файл целиком" | Промпт со структурой + форматом операций |

## Грабли (учесть при реализации)

1. **Парсер блоков** — regex терпимый: лишние пробелы, разные маркеры кода, отсутствие языка. Если не распарсилось — показать сырой ответ.
2. **Длинные ответы** — DeepSeek может обрезать. Ограничение: 3-5 файлов за раз, каждый до ~500 строк.
3. **JSON-escape при вставке в WebView** — использовать `JSONObject.quote()`.
4. **`project_write:` с base64** — содержимое может содержать `:` и переводы строк, b64 безопасен.
5. **Бэкап перед применением** — обязательно, в `~/vibe/.backups/`.
6. **Лимит итераций** — не больше 5-7, иначе сжигаем токены.
7. **Отмена** — пользователь должен прервать цикл в любой момент.
