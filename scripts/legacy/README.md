# Legacy-скрипты

Эти скрипты остались от старой архитектуры (a11y-эпоха, до WebView + HTTP IPC).
Сейчас **не используются** приложением. Оставлены для истории и на случай,
если понадобится поднять старый флоу для CLI-экспериментов.

## Что тут и почему

| Файл | Что делал | Почему legacy |
|---|---|---|
| `receiver.py` | Python-сервер, слушал сокет 127.0.0.1:8766 | Заменён на HTTP `ai-tasker-server` (8767) |
| `aib` | Обёртка над aib-auto | Не вызывается из живых скриптов |
| `aib-watchdog` | Следил за aib | Вместе с aib |
| `aictl` | Управление a11y-сервисом | a11y больше не используется |
| `aictl-up` | Подъём a11y-сервиса | То же |
| `ai-cycle` | Цикл автономной разработки | Заменён на Dev-режим в приложении (WebView + apply-patches) |
| `ai-dev` | Ручной запуск авторазработки | То же |
| `grab` | Забирал код-блок из DeepSeek через a11y | Заменён на TermuxReadLast в JS-мосте |
| `logrotate-aib` | Ротация логов aib | Вместе с aib |

## Что НЕ legacy (живые, лежат уровнем выше)

- `ai-tasker-server` — HTTP 8767, основной IPC
- `ai-router` — маршрутизация команд
- `ai-tasker-daemon` — файловый fallback (inbox/outbox)
- `aib-auto` — **живой fallback для CLI**: `ai-router "напиши скрипт X"` из Termux
- `apply-patches`, `export-source` — Dev-режим
- `auto-release`, `vk-post` — релизы и ВК-постинг
- `ai-run`, `tinfo` — утилиты для ручного использования

## Если хочешь вернуть что-то обратно

Скопируй из `legacy/` в `scripts/` (уровнем выше) и добавь в `release-utils/install.sh`
в список живых. Но сначала проверь, что зависимость (a11y-сервис, сокет 8766)
действительно нужна — в текущей архитектуре её нет.
